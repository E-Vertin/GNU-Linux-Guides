# Gentoo rootfs on ZFS Installation Guide

**Please do note that Gentoo Live GUI ISO does NOT provide ZFS support, adopt Gentoo Minimal Install ISO instead.**

## Preface

ZFS was originally developed by SUN Microsystems and was adopted by Sun Solaris. It later became open-sourced in 2005 and was ported to FreeBSD in 2007. In 2008, Brian Behlendorf and his team attempted to port ZFS to GNU/Linux, but due to incompliance with licensing terms, it could not be merged into the Linux source tree.

If you are reading this article, I assume that you have the basic understanding of ZFS and willing to give it a try. Please be aware that ZFS has higher hardware requirements, and I/O performance and RAM can severely affect its performance.

There are two substantial concepts in ZFS: `zpool` and `dataset`. It will be a huge help to your later practice by understanding them clearly.

`zpool` can be taken as a big container consists of several virtual devices, while `dataset` are "file systems" reside in the container.

**For consistency, this article will be about booting Unified Kernel Images generated by `dracut` on `systemd-boot`, and `/efi` will be a seperate partition and `/` resides in a ZFS partition**

## Preparing disks

The disk should at least contain two partitions. One for EFI System Partition and the other for your root file system.

> Attention: EFI System Partition CANNOT be contained by ZFS, `systemd-boot` is INAPPLICABLE.

### Alternating the partition table

1. Checking the disk

    Issue this to list local disks and partitions:

    ```bash
    lsblk
    ```

    > Mark down locations of disks and partitons, `/dev/sda` and `/dev/nvme0n1` for instance.

2. Manipulate the partition table via `cfdisk`

    Execute this to start:

    ```bash
    cfdisk /dev/<disk>
    ```

    - Create a partition with the size of 1 GB for ESP and specify it with the `EFI System Partition` label.

    - Create a partition for ZFS and label it with `Linux filesystem`

### Create a `zpool` container

  **`zpool` will be using `/etc/hostid` to identify the host machine, issue `zgenhostid` before creating a container**

  > Tips: check disks again and mark them down with `lsblk`.

  - Create a generic `zpool` container

    Issue this to create a `zpool`:

    ```bash
    zpool create -o ashift=12 -o autotrim=on -O acltype=posix -O xattr=sa -O normalization=formD -m none <zpool name> /dev/<partition>
    ```

    > For example:
    >
    > `zpool create -o ashift=12 -o autotrim=on -O acltype=posix -O xattr=sa -O normalization=formD -m none root_zpool /dev/nvme1n1p2`

    > There are plenty of parameters for a `zpool`, below are the description for the above:
    >   - `ashift=12` manually sets the sector size to 4096 bytes (which is the sane default for most disks).
    >   - `autotrim=on` enables TRIM, which is crucial to SSDs.
    >   - `acltype=posix` sets Access Control List to use the POSIX type.
    >   - `xattr=sa` configures the container to use system attributes for files.
    >   - `normalization=formD` tells the container to normalise file names in case become unreadable on other OSes while on NFS/SMB sharing
    >   - `-m` will set the mountpoint for the top level `dataset`, which should be `none` here.

    > Tips: To apply LUKS full disk encryption, initialise LUKS container first and unlock it for the virtual device of `zpool`.

### Create file systems and ZFS Dataset

1.  Format the ESP
    
    Issue this to format the ESP:

    ```bash
    mkfs.vfat -F32 -n <file system label> /dev/<partition>
    ```

    Also, have to ESP mounted to `/efi`

2.  Establish `Dataset`
  
    > Caution: a top level `Dataset` with the same name will be established upon creating a `zpool`, and is not capable of destroying unless the whole `zpool` was issued.

    Execute this to create a sub-`Dataset` and make it uncapable of mounting:

    ```bash
    zfs create -o mountpoint=none <zpool name>/<dataset name>
    ```

    > For instance, `zfs create -o mountpoint=none root_zpool/gentoo`

    Run these commands to create lower level `Dataset` to manage the whole root tree:

    ```bash
    zfs create -o mountpoint=/ -o canmount=noauto <zpool name>/<sub-dataset name>/<dataset name>
    zfs create -o mountpoint=/home <zpool name>/<sub-dataset name>/<dataset name>
    zfs create -o mountpoint=/var/log <zpool name>/<sub-dataset name>/<dataset name>
    (Goes on like these...)
    ```

    > For example:
    >  ```bash
    >  zfs create -o mountpoint=/ -o canmount=noauto root_zpool/gentoo/rootfs`
    >  zfs create -o mountpoint=/home root_zpool/gentoo/home
    >  zfs create -o mountpoint=/var/log root_zpool/gentoo/log
    >  (Goes on like these...)
    >  ```

    Configure `Dataset` properties to make the root file system the `bootfs`

    ```bash
    zpool set bootfs=<zpool name>/<sub-dataset name>/<root dataset name> <zpool name>
    ```

    > Take this as an example:
    >
    >  ```bash
    >  zpool set bootfs=root_zpool/gentoo/rootfs root_zpool
    >  ```

## Perform the installation

   Issue these to re-import `zpool` and set `/mnt/gentoo` as the temporal root before mounting `Dataset`:

   ```bash
   zpool export <zpool name>
   zpool import <zpool name> -R /mnt/gentoo -N
   ```

   Mount file systems starting with the root directory:

   ```bash
   zfs mount <zpool name>/<sub-dataset name>/<dataset name>
   mount --mkdir /dev/<ESP> /mnt/gentoo/efi
   ```

## Steps differ from standard installation

### Before `chroot` to enter the newly installed OS

   To ensure DNS resolves properly, it is stated that `/etc/resolv.conf` has to be copied to the new OS.

   Also, to ensure `zpool` work properly, `/etc/hostid` was required as well.

### File systems utilities and libraries

   Please make sure `sys-fs/zfs` has enabled `disk-kernel-cap` and `modules` in USE Flag configuration, which should be enabled by default.

### `dracut` configuration

   To mount file systems on start-up, append these in `dracut` configurations:

   ```bash
   nofsck="yes"
   add_dracutmodules+=" zfs "
   kernel_cmdline+=" root=ZFS=AUTO rw zfs.force=1 "
   ```

   > If multiple `zpool` reside in the system have the property `bootfs` set, please change `root=ZFS=AUTO` to `root=ZFS=<zpool name>/<sub-dataset name>/<root dataset>`

   **To apply changes, rebuild the initramfs**

   > Caution: if the `zpool` resides in a LUKS container, do also append `crypt` to the `add_dracutmodules` entry and add `rd.luks.uuid=<UUID of the LUKS physical partition>`.

### `init` programme settings

  - For `OpenRC` users:

    Please add `zfs-import` and `zfs-mount` to boot runlevel:

    ```bash
    rc-update add zfs-import boot
    rc-update add zfs-mount boot
    ```

  - For `systemd` users:

    ```bash
    systemctl enable zfs-import.target
    systemctl enable zfs-import-cache
    systemctl enable zfs-mount
    ```

    > To share `Dataset` over NFS/SMB, enable `zfs-share`.

    > Tips: `zfs-zed` can be used to monitor `zpool` status and have it recorded, but it's optional.

## Finalising the installation

   Now, you are good to follow the Gentoo Handbook to finish the installation.
